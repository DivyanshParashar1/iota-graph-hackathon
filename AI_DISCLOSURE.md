# AI assistant disclosure

The hackathon allows AI assistants if their use is disclosed and the team can explain the model, queries,
architecture and decisions. This file states what was AI-generated and what the human owns.

## What the AI did

* **Tool**: Claude Code (Anthropic), running autonomously in one cloud session per version.
* **Input**: a human-written product spec (`idea.md`), a human-written v2 build plan (`plan.md`), verified
  FalkorDB syntax notes (`reference/FALKORDB_VERIFIED.md`), and an offline environment prepared by the human.
* **Output (v2)**: most of the code on this branch: the `ripple/` package (the LLM provider layer, the
  onboarding stage machine and store, the four agents, upload intake, spec validation and application, the
  expert store and runtime, the ontology-aware tools, the API), every file in `graph/queries/`, the React UI,
  the tests, the demo CLI, the Docker and Render files, the generated README, `docs/numbers.md` (measured by
  `scripts/report_numbers.py`), `docs/KNOWN_ISSUES.md` and `docs/FEATURES.md`.
* **The agents' prompts** (`ripple/onboarding/agents/prompts/*.md`) were written by the AI and are the part of
  this repository most worth a human read: they are the product's behaviour, not an implementation detail.
* **No synthetic corpus.** v2 ships no data at all. The only generated-data affordance is the **Synthesize**
  button, which asks a model to invent plausible form answers for a demo; every value it writes is stored with
  `source: "synthetic"`, rendered with a badge, and flags the tenant. Nothing else in the product may invent a
  value, and the agents' prompts say so explicitly.
* **At runtime every agent step is a real LLM call.** There is no scripted mode and no fake client to fall
  back on. The default provider is Claude Code on the machine's own login (`claude -p`, its own tools off);
  OpenRouter and the Anthropic API are selectable. Answers from an expert role are checked by an id validator
  against the ids the tools actually returned.
* **v1** (a DataCo-based control tower, with a synthetic document corpus generated by committed template code)
  was built the same way in an earlier session. It is preserved at commit `04d4bd4` / local tag `v1-dataco`
  and is not part of this branch.

## What the AI did *not* decide

The plan it executed (`plan.md`) is human-written, including the four-agent split, the "no fakes" rule, the
mandatory human approval of the ontology and of each expert role, and the decision to leave the
post-onboarding application unspecified. Where the AI deviated from the plan it recorded the deviation and the
reason in `docs/KNOWN_ISSUES.md`.
